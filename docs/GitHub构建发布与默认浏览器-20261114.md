## 自动Tag发布

先同步 `package.json.version`、`src-tauri/Cargo.toml` 和 `src-tauri/tauri.conf.json.version`，并同步工程构建号与 `bundle.macOS.bundleVersion`。提交源码和两份工作流后，推送对应 `v版本号` Tag，例如 `v0.1.0` 或 `v0.2.0-beta.1`。也可在Actions中手工选择分支/Tag，`tag`输入留空时使用工程版本，或填写与工程版本一致的Tag；该平台三个架构成功后自动创建Tag和Release。已有同名Tag指向不同提交时拒绝覆盖。

两份工作流由同一次Tag推送独立触发，也可以分别手动运行。手动创建Tag使用GITHUB_TOKEN，按GitHub规则不会再次触发另一套Tag工作流，因此手动发布时请从同一提交分别运行两份工作流；若需两平台一起自动执行，请推送Tag。每个平台三个架构全部成功后，聚合资产、复核commit/Tag/架构/大小/SHA-256，再创建或更新同一Tag的GitHub Release；两平台同时首次创建Release时会容错重查。预发布Tag自动标为Prerelease。资产以版本+平台+架构命名，互不覆盖；重跑同一个Tag只覆盖同名资产。一个平台失败不会阻止另一平台发布已验证的完整平台资产，也不会声称失败平台已发布。

使用仓库自带 `GITHUB_TOKEN` 的 `contents:write` 上传，不需PAT。若组织禁用工作流写权限，需要管理员放行；本次未上传工作流、推送Tag或在GitHub触发构建。`ci-build.mjs` 和 `publish-release.mjs` 不包含固定的 `0.1.0`，可用于后续版本。

## 签名配置

默认构建无需签名Secrets，GitHub会发布可下载的未发行者签名安装包，系统可能显示验证提示。每份 `_build.json` 附带真实的 `developerIdSigned`、`notarized`、`windowsSigned` 标记；不要把未配置证书的包宣传成已签名/公证。

若需macOS签名公证，在仓库Secrets完整配置：

- `APPLE_CERTIFICATE`：Developer ID Application证书P12的base64。
- `APPLE_CERTIFICATE_PASSWORD`：P12密码。
- `APPLE_SIGNING_IDENTITY`：完整Developer ID身份名称。
- `APPLE_ID`、`APPLE_PASSWORD`（App专用密码）、`APPLE_TEAM_ID`：Apple公证凭据。

证书仅导入临时钥匙串，任务最后清理；部分配置不会静默降级成未签名。完成签名后校验codesign和stapler票据，公证失败就不发布该架构。Windows当前没有配置Authenticode签名，构建信息明确标为false；安装器仍包含应用图标。

## 默认浏览器

设置页新增“设为默认浏览器”和“刷新状态”，分别显示HTTP/HTTPS实际默认状态，不以按钮点击成功代替系统确认。

- macOS：Info.plist声明http/https候选；用户点击后请求LaunchServices设置，安装到Applications后使用。开发态裸二进制会提示先安装app；未完成系统确认时仍显示未默认。
- Windows：NSIS按当前用户注册 `RegisteredApplications`、Capabilities和 `SAB.Url`，参数命令正确引用exe路径及URL；点击设置按钮可补注册并打开 `ms-settings:defaultapps` 的应用入口。系统选择由用户完成，绝不写入或伪造UserChoice哈希；卸载仅清理本安装目录仍拥有的注册项。
- 系统链接：Windows启动参数与单实例回调、macOS `RunEvent::Opened`进入有限队列；前端就绪后串行打开新标签。只接受HTTP/HTTPS，拒绝凭据、文件和脚本协议；已运行时将窗口带回前台。

本次测试不修改开发机默认浏览器。查询与链接队列使用受限IPC，只授权main外壳；远程网页无设置系统默认项的权限。
