# 轻页 SAB 浏览器 Tauri 候选版设计与验证方案

版本：v0.3  
日期：2026年11月8日  
作者：lq  
状态：技术路线已按产品决定采用 Tauri；本文件为候选版设计与验证基线，尚未生成浏览器实现或安装包，也未取得性能实测结果。  
产品名称：中文名「轻页」，英文名「SAB」，双语展示使用「轻页 SAB」。  
英文释义：Small And Beautiful，表达小而美的产品理念。  
命名确认日期：2026年11月8日。

本文替代 v0.1 与 v0.2 中的技术推荐、功能优先级与放行条件。原有极简主页、收藏交互和本地整理方向保留；AI 工具调用不再作为候选版的优先项或发布阻断条件。

## 1 已确定的方向

采用 Tauri 与系统 WebView，围绕轻、快、美和日常浏览体验构建候选版。优先完成两种主页、收藏中心、非 AI 自动归类、Chrome 与 Edge 书签导入、最近打开及设置默认浏览器。

技术组合建议为 Tauri 2、Rust、Vue 3、TypeScript、Vite 和 SQLite。版本在实施时锁定，本文不将任一依赖称为已验证的最新版本。前端以少量组件和自定义样式实现，不引入大体积后台 UI 框架；Rust 负责数据与平台适配。

macOS 使用系统 WKWebView，Windows 使用 WebView2，明确接受两端引擎不同的取舍。网页兼容性、会话存储和系统交互仍需在真实应用中分别测试。[Tauri WebView 说明](https://v2.tauri.app/reference/webview-versions/)。

本轮不因 Mac 无法按原方式接入 Playwright 而重新切换回 Chromium，也不额外嵌入 CEF 或另启 Chromium 绕过这一差异。需要产品重新决策的真正问题是日常浏览、数据安全和基础交互无法达到要求。

| 能力 | 候选版安排 | 验证边界 |

| Mac 与 Windows | 核心 | 两端均有原生应用和安装包，不能只验证网页原型 |
| 极简搜索主页 | 核心 | 默认只有搜索框，使用必应；本地加载，无资讯推荐 |

| 自定义主页与搜索引擎 | 核心 | 启动页与搜索引擎分开配置 |
| 收藏浮层 | 核心 | 一个常驻入口、搜索、分类页签与列表，无书签栏 |
| 非 AI 自动归类 | 核心 | 本地规则、待整理、手动纠正与撤销 |

| 旧网站登录状态迁移 | 后续专项 | 不保证完整迁移，不作为候选版体验验证前置条件 |
| 外部 Playwright CLI MCP | 后续预研 | 不作为本版必交能力，测试通路与产品接口分别记录 |

| 轻量笔记 | 后续 | 纯文本或轻量 Markdown、来源引用和本地保存起步 |

密码需求没有取消。内部候选版可以带明确的未完成功能清单进行体验测试；若密码等基础能力未通过，不得宣布已经能全面替代 Chrome，正式测试版的范围需明确列出。

浏览基础还需覆盖：前进后退、刷新、地址输入、多标签和多窗口、恢复关闭标签、页内查找、缩放、上传下载、权限提示、网页错误与证书错误、清理浏览数据、隐私会话、打印和会话恢复。每项记录“通过、部分支持、未完成”，不能因为能展示网页就视为全部具备。

暂不做资讯、广告推荐、壁纸商店、内置模型、积分、团队工作区和自建账号。候选版不承诺 Chrome 扩展兼容；不将第三方密码管理扩展视为已经完成的密码方案。

## 3 主页与收藏交互

### 3.1 浏览器框架

默认使用标签行和导航行。导航包含前进后退、刷新、地址搜索框、收藏中心和菜单。macOS 保留系统窗口控制，Windows 适配窗口按钮、拖动和贴靠；两端共享视觉规范并遵守系统行为。

启动默认打开内置极简主页；新标签默认仍打开内置主页。可配置启动时恢复上次标签或打开指定网址，搜索引擎独立设置。外部启动页不注入最近打开等私人数据。

极简主页默认仅一个居中略偏上的搜索框，默认必应。最近打开默认关闭，在设置开启后出现，可展开或收起。收藏主页保留较小搜索框、用户固定项、分类导航与紧凑网格或列表；大量内容采用列表与虚拟化。

最近打开定义为本机普通网页最近访问记录，按 URL 保守去重，初始展示 6 项，可展开至 20 项。排除隐私会话、内部页与失败导航。隐藏主页项目与删除历史分别提供，不使用含糊的“清空”暗示相同作用。

### 3.2 收藏浮层

保留一个常驻收藏入口，点击后打开搜索与列表面板。参考程序坞启动器的浮起感，不复制复杂图标放大效果。宽度建议 560–640 逻辑像素，高度不超过窗口可用高度的 75%，小窗口自适应。

顶部搜索标题、域名、URL 和标签；中间为全部、常用及有内容的分类页签；主体为站点图标、标题、域名和分类；底部提供收藏当前页面或编辑当前收藏、进入完整管理页。

`Cmd/Ctrl+D` 收藏当前页，`Cmd/Ctrl+Shift+O` 打开收藏中心，`Cmd/Ctrl+L` 聚焦地址栏。上下键选择列表，Enter 打开，平台修饰键配合 Enter 新标签打开；Tab 遍历焦点，分类区域使用左右键切换。面板关闭时恢复焦点。

收藏一次动作即可保存。高分规则命中后显示归类结果与更改入口，无法确定时进入待整理。重复收藏默认编辑已有项，明确选择后才另存副本。导入、批量移动和重新归类提供预览与撤销。

### 3.3 视觉与动效

跟随系统浅深色，以中性背景、清楚正文、细分隔线和少量强调色为主。使用系统字体和本地静态资源，不依赖远程字体。输入框圆角约 12、浮层约 18 逻辑像素，点击区至少 32×32，正文对比度与键盘焦点独立检查。

浮层进入约 140–180 ms，退出约 100–140 ms，列表切换约 100–140 ms，均为候选参数。输入即时响应，不等待动画完成；支持减少动效与减少透明度。大面积持续背景模糊、逐条飞入、循环动画和为装饰常驻的计时任务不进入默认界面。

原生网页子视图可能影响 HTML 浮层的覆盖、裁切与点击命中，必须先验证。若改用原生弹窗，继续验证输入法、焦点、多屏、缩放、拖动与窗口失焦行为。

## 4 不使用 AI 的整理

本地规则只读取已经存在的 URL、标题、目录、标签和用户纠正记录，不批量访问网页抓正文。初始分类建议开发、设计、工作、学习、阅读、生活、购物、娱乐和待整理；空分类隐藏，可改名、合并和自建。

优先级依次为：单条手动锁定、用户域名或路径规则、保留的导入目录、内置域名路径规则、关键词与纠正记录评分、待整理。每条收藏一个主目录，可有多个标签。多用途站点不能仅凭域名归类。

规则输出分数和理由，初始门槛可试用最高分至少 80 且领先第二名至少 20；这是规则分数，不是正确概率。用户修改后不自动改回，是否扩展为整个站点规则由用户选择。规则更新默认只影响新收藏。

去重不统一删除查询参数或锚点，不把 HTTP 与 HTTPS 无条件合并。域名解析使用公共后缀规则。导入保留目录；主动重新整理才生成变更预览。

以至少 500 条人工标注样本验证，区分调规则样本与独立验证样本，报告正确率与覆盖率。候选目标是已自动归类项目正确率达到 90%，允许不确定项目留在待整理；该数值尚无实测支持。

## 5 Tauri 架构与数据

```text
本地 UI WebView
标签 地址栏 主页 收藏中心 设置
              │ 受限命令
Rust 应用服务
标签生命周期 收藏检索 分类规则 导入 历史 会话配置
              │ 平台适配
网页内容 WebView
macOS WKWebView        Windows WebView2
              │
应用 SQLite    WebView 网站数据    系统凭据保护
```

第三方网页使用独立原生 WebView，不能用主页里的 HTML iframe 充当浏览器内容区。Rust 管理导航、标题与地址更新、新窗口、权限、下载、视图大小和生命周期。普通标签共享正确的持久化网站数据环境，隐私会话使用独立且可销毁的数据环境，并验证系统支持范围。

本地 UI 与第三方网页分配不同的 capabilities。远程网页不得获得文件读写、Shell、SQL、密码访问和完整应用命令权限；所有敏感命令检查调用来源、窗口标识和参数，不依赖前端隐藏按钮。[Tauri capabilities](https://v2.tauri.app/security/capabilities/)。

自建 SQLite 作为收藏、目录、规则、历史和设置的单一数据源，所有业务写入经 Rust 服务层，搜索索引可重建。可使用 Tauri SQL 生态支持，但不向远程页面暴露通用 SQL 执行接口。[Tauri SQL 插件](https://v2.tauri.app/plugin/sql/)。

收藏记录包括稳定 ID、URL、标题、目录、标签、固定顺序、创建修改时间、规则理由和手动锁定。导入有批次 ID 和来源；同步预留独立全局标识、修订与删除标记。历史与标签恢复记录分开，恢复 URL 不代表能恢复网页所有内存状态或未提交内容。

本版不再复用 Chromium BookmarkModel、Chrome 历史数据库或 Chromium 密码管理器作为本浏览器的数据层。旧浏览器数据仅作为导入来源，不能直接与本应用共用目录。

## 6 迁移与登录

首次运行提供可跳过的主页模式选择、书签导入和默认浏览器设置。导入流程展示来源档案、项目数量与目录预览，导入后报告新增、重复与失败，允许撤销本次新增，不影响之后的独立修改。

Chrome 和 Edge 提供本机可读书签档案导入与标准 HTML 文件导入，并支持本浏览器导出 HTML。本机格式适配是本产品实现，需覆盖版本和多档案；读取失败时提供文件导入兜底。源文件只读，不擅自修改旧浏览器。[Chrome 书签交换说明](https://support.google.com/chrome/answer/96816)、[Edge 导入说明](https://support.microsoft.com/en-us/edge/import-your-favorites-and-passwords-in-microsoft-edge)。

本浏览器内重新登录后的 Cookie 与网站存储应正确持久化；关闭重启、多个普通标签、隐私会话、清理单站点数据和清空全部网站数据分别测试。登录有效期仍受网站与系统凭据条件影响。

密码保存、自动填充和 CSV 导入做专项验证：分别检查两端 WebView 实际支持，以及必要的系统凭据保护和应用密码管理实现。不能用“会话保持通过”替代“密码保存通过”，也不能将 WebView 与 Safari 或 Edge 完整密码管理功能等同。

若需自建凭据存储，采用成熟系统凭据保护，不在 SQLite、日志或普通配置里存明文密码。自动填充校验实际顶层来源、frame 来源和用户选择，拒绝跨域错误填入；导入 CSV 不上传、不记录内容，成功后提醒用户处理明文源文件，不擅自删除。

旧 Chrome 或 Edge 网站会话迁移后续专项研究，不保证全站免登录，不共用活动档案，不绕过系统加密。候选版可先重新登录常用站点，公开报告已验证的会话表现。密码与迁移能力未通过时，在候选版限制清单中明确记录，进入日常替代发行前评审。

## 7 默认浏览器与平台发行

首批目标为 Mac Apple Silicon、Mac Intel 和 Windows x64；最低系统版本在依赖版本和设备覆盖验证后锁定。两端维护同一代码主干，由对应构建环境生成发布产物。

| 平台 | 首选产物 | 发行要点 |
| --- | --- | --- |
| Mac Apple Silicon | ARM64 DMG | 应用签名、公证、外部链接打开、升级保留数据 |
| Mac Intel | x64 DMG | 单独构建与测试，避免默认 Universal 增大下载 |
| Windows x64 | NSIS EXE | 安装卸载、签名、浏览器注册、WebView2 检查 |

Tauri 官方支持 Mac DMG，以及 Windows NSIS 和 MSI 等分发方式。Windows 默认优先使用 Evergreen WebView2 运行时；已存在则复用，缺失时引导安装，避免默认携带固定版本离线运行时。[DMG 分发](https://v2.tauri.app/distribute/dmg/)、[Windows 安装与 WebView2 策略](https://v2.tauri.app/distribute/windows-installer/)。

包体积分别记录应用安装包、安装后应用、运行时额外下载和安装体积；使用中缓存另计。是否能达到几十 MB 量级需正式构建后实测，本方案不作数值承诺，也不能把应用包体小等同于网页运行省内存。

默认浏览器采用系统注册和用户确认，支持 HTTP、HTTPS 和可选 HTML 文件关联，完成后回读结果，避免反复劝导。[Windows 设置入口](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-default-apps-settings)、[Mac 默认浏览器](https://support.apple.com/en-asia/102362)。

应用更新可采用 Tauri updater 与托管发布文件，使用更新包签名并保护私钥；平台代码签名与 updater 签名分别处理。验证网络失败、错误签名、数据库迁移和重新启动保留数据，不能宣称所有更新都是增量更新。[Tauri updater](https://v2.tauri.app/plugin/updater/)。

Mac 的网页引擎更新依赖系统 WebKit，Windows 则依赖 WebView2 更新；应用自己的更新不等于升级两端网页引擎。记录支持系统范围和过旧运行时的处理，不关闭证书校验或引擎沙箱来适配网站。

## 8 候选版验证与放行

### 8.1 先验证最容易返工的事项

第一批检查原生多 WebView、收藏浮层覆盖与输入、普通网站登录持久化、网页新窗口和下载。先在真实 Mac 与 Windows 应用上完成，再投入完整视觉打磨。外部 AI 自动化不进入这一批门槛。

### 8.2 分阶段交付

| 阶段 | 交付物 | 放行条件 |
| --- | --- | --- |
| 技术骨架 | 双端窗口、多标签、导航与本地存储 | 内容区、浮层、输入法与网站数据边界可行 |
| 核心体验候选版 | 两种主页、收藏搜索分类、规则整理、导入与最近打开 | 数据正确，主要路径可操作，错误可恢复 |
| 日常使用验证 | 代表网站、登录、上传下载、权限、默认浏览器 | 兼容矩阵完成，密码等未完成项明确可评审 |
| 发行候选版 | 三种安装包、签名与更新、性能报告 | 安装升级不丢数据，无阻断级问题 |
| 后续能力 | 同步、笔记、AI 接口 | 独立立项和验证，不延迟已通过的核心体验 |

计划按阶段验收，不沿用此前 Chromium 版本的周期估算；工具链建立后再估算实际开发量和日期。内部候选版与可公开日常替代版本分开标记。

### 8.3 功能验收

- 默认必应、两种主页、自定义启动页与最近记录符合设置，断网时本地主页和收藏可用。
- 收藏入口、键盘搜索、分类、编辑、固定、删除与撤销可用，10000 条收藏不阻塞操作。
- 导入保留目录，重复可控，不改写来源，失败和撤销范围清楚。
- 多标签、多窗口、新窗口链接、上传下载、查找缩放和恢复关闭标签在两端可用。
- 登录重启保持、共享范围、单站点清理和隐私会话符合实际说明；密码能力单独记录。
- 真实应用中验证中文输入法、减少动效、深浅色、多屏缩放、屏幕阅读器和焦点恢复。
- 远程网页无法调用敏感本地命令，证书异常与权限提示来源清晰。
- 默认浏览器、首次安装、更新失败和数据迁移可验证。
- 对 DRM、WebAuthn、视频会议、代理证书与必要企业站点建立兼容矩阵，未通过不得宣称全面兼容。

内部应用测试可评估 Tauri 推荐的 WebdriverIO 路径，配合真实桌面人工验收；这与提供外部 Playwright 产品能力分别记录。纯网页测试不能替代原生内容区、系统窗口和发行检查。[Tauri 应用测试](https://v2.tauri.app/develop/tests/webdriver/)。

### 8.4 性能验收

热启动到可输入 P95 候选目标不超过 800 ms，冷启动不超过 2 s；10000 条收藏时面板可输入不超过 100 ms、索引就绪的查询刷新不超过 50 ms。以上都是待验证目标，正式优化构建和确定参考设备后再锁定。

使用空主页、5 站点、20 混合标签、长期闲置标签、视频和长表单进行测试。至少 30 次启动样本，报告中位数与 P95；内存聚合应用与相关 WebView 子进程，运行时复用和共享进程的归属口径明确说明。Mac 与 Windows 使用各自一致口径，不直接比较不同系统的绝对内存值。

与干净 Chrome 档案及相近日常配置分别比较，不预先承诺省内存百分比。记录 CPU、空闲唤醒、耗电和交互掉帧，包体积单列。先解决同步磁盘操作、重复索引、过量监听和持续动画；不强行销毁音视频、上传下载和未提交表单页面。

## 9 后续能力

### 9.1 AI 接口

本版不提供给普通用户开启的调试端口，不因双端外部 Playwright 支持不完整而阻断发布。开发调试与内部测试接口仅在受控环境启用，按构建配置和权限隔离。

后续先评估 Windows WebView2 的 CDP，再评估两端受控 CLI 或 MCP。跨域 frame、复杂页面、系统对话框、任务标签与登录环境分别验证；不把另一浏览器执行的结果视为本浏览器执行结果。用户未授权时不自动修改 AI 客户端配置。

### 9.2 免自建服务器同步

本地使用不要求登录。后续可连接用户自己的 OneDrive 或 Google Drive 保存加密同步数据，第三方授权不等于继承 Chrome 或 Edge 私有同步内容。先接一家服务商并实测目标网络和账号类型。[OneDrive 应用目录](https://learn.microsoft.com/en-us/graph/onedrive-sharepoint-appfolder)、[Drive 应用数据目录](https://developers.google.com/workspace/drive/api/guides/appdata)。

先同步收藏、目录、规则与偏好；历史摘要由用户选择，密码、Cookie 和无痕数据不进入初期同步。云端保存版本化操作和快照，不直接同步使用中的 SQLite 与 WebView 数据目录。

实现稳定标识、幂等操作、版本校验、删除标记和冲突恢复；长期离线设备恢复时先拉取有效快照，防止旧数据复活。授权失效或配额不足保留本地数据。上传前加密，新设备通过配对或恢复码取得密钥，完整验证密钥丢失后的恢复边界再发布。

### 9.3 轻量笔记

按需打开侧栏，先做标题、文本或轻量 Markdown、来源 URL、搜索和自动保存，支持选中文字主动加入引用与 Markdown 导出。删除收藏不连带删除笔记。后续再研究高亮、剪藏和同步，不增加复杂知识图谱或团队协作。

## 10 风险与验证责任

| 风险 | 验证要求 |
| --- | --- |
| 两端系统引擎差异 | 常用站点、权限、媒体、网页存储和版本矩阵分别测 |
| 原生视图影响浮层 | 开发初期实测覆盖、输入法、焦点和多屏，避免后期重构 |
| WebView 不等于完整浏览器 | 下载、弹窗、密码、会话、清理和恢复各自明确交付状态 |
| 小安装包但运行仍耗资源 | 分开记录安装体积、运行时、进程内存、CPU 与耗电 |
| 密码和旧会话迁移复杂 | 保留需求并专项验证，不能用普通登录测试代替 |
| 远程网页取得本地权限 | 按来源与命令隔离，敏感参数在 Rust 层检查 |
| 云端与本地合并错误 | 同步后置，本地导出、版本恢复和删除传播先设计 |
