# Chrome 密码导入与手动填表

时间：2026-11-16；作者：lq。

## 导入

在 Chrome「密码管理工具 → 设置 → 导出密码」导出 CSV，然后在轻页 SAB「设置 → 密码管理 → 选择 Chrome 密码 CSV」。界面解析后先显示导入数量，用户确认后每 25 条逐批导入，最多 5000 条，文件不超过 20 MB。

Chrome CSV 中 HTTP(S) 网站、用户名和密码字段会保留原始内容；空密码、应用账号、畸形网址及重复行会跳过。已经保存的同一来源和用户名不会覆盖。macOS 使用系统钥匙串，Windows 使用当前用户凭据管理器。SQLite 仅保存不含密码的账号索引。平台安全存储访问失败的条目会单独统计，用户可重新导入原文件补齐。

Chrome 导出的 CSV 是明文。导入后请从下载文件夹删除。Passkey 不属于 CSV 中的普通账号密码，不会被迁移。

## 手动填表

HTTPS 网页加载后，点击地址栏右侧钥匙按钮，选择当前网站的账号。应用会再次检查标签真实 URL 与账号来源完全一致，支持常见唯一密码框和对应表单内的用户名框。应用只填写，不提交；表单缺失、多重密码框、注册新密码字段、跨站表单或 iframe 情况会拒绝自动填写。页面没有通过明确操作保存的新密码也不会自动进入密码库。

账号索引提供设置页搜索和单条删除。删除先清理系统密码库，再删除本地索引；系统拒绝访问时保留索引，便于重试。

## 测试边界

逻辑测试使用仅存在于测试进程内的假密码库。macOS 钥匙串验收只创建、读取并删除随机 ID 下的合成测试密码，不读取已有条目。原生工作区验收使用隔离数据库和合成 CSV 导入、重复跳过、删除。Windows 凭据管理器依赖不在本机验证，需 Windows 设备构建和验收。Passkey、自动保存新密码、跨域 iframe、分步登录和每站自定义字段映射均未实现。
